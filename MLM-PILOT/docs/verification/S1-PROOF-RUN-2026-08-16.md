## Deliberate deviations from the spec's sketches, argued in the files

- **D1** `sim_clock.clock_date` (the spec's `current_date` is a PostgreSQL
  reserved word).
- **D2** pause and billing-day-change events materialise their
  effective-from renewal index and pause-until date at event time, so the
  derivation is a pure replay (migration 021's resolve-into-data principle).
- **D3** attempts snapshot their classification (ladder step, class,
  member-fault flag), because classifications are effective-dated data and
  an attempt must carry the answer it was judged by.
- **D4** run rows carry the pipeline step 12 assertions as columns.
- **D5** `billing_day` is checked 1 to 28, not 1 to 31: Howard's OQ3 ruling
  made the pick rule structural; anchors keep full clamp handling (FM4).
- **D6** the schedule formula indexes from ZERO periods after the anchor:
  the spec sketch's `n * frequency_months` would put the first renewal one
  full period late, contradicting ruling R1's "the first renewal bills on
  that date" and the spec's own worked example; rulings are law over
  sketches.
- **D7** the engine epoch (above).
- **D8** ALL system-fault failures (internal_config, config, duplicate,
  infra) leave the member's state untouched and route to the attention
  queue; the spec allowed internal_config to route to card_update_required
  OR the queue, and punishing the member for our defect was rejected.
- **D9** the crash lever is a session setting, not an eleventh table.

## What the gates should probe hardest

1. **Deviation D6** (first renewal ON the anchor). If the architect meant
   the sketch formula literally, every date in this build shifts one period;
   the worked examples pass either way only because their anchors were
   stated as billing dates. Confirm against ruling R1's words.
2. **D8's routing call** for internal_config (attention queue only, state
   untouched). DANA bills a fresh attempt every month forever until staff
   fix the credential; if Howard would rather the member be moved to
   card_update_required after N system-fault months, that is a data-shaped
   rule that does not exist yet.
3. **The auto-cancel derivation** (12.7): the sweep derives unpaid months
   from period coverage rather than replaying full state history; the OQ2
   pause-reset window is approximated as "no pause event whose window
   reaches into the counted months". Adversarial pause-timing scenarios are
   the place to attack it.
4. **Early resume** refuses inside the first paused month (whole-month
   shifts only); the function says so loudly, but it is a narrower surface
   than spec 12.2's "re-derives with the actual months skipped".
5. **The gather loop's linear scan** of active subscriptions per tick is
   fine at pilot scale and lazy at 100 times that; an index-driven due-date
   window is an S2 optimization, deliberately not taken now.
6. **The reconciler trusts the script table as the processor's ledger**; on
   the S2 real rail the same step must be pointed at the processor retrieve
   with the same three-way outcome (answered, never-received, unreachable).
   The seam is one function (`fn_sim_submit` and reconcile step 2).
